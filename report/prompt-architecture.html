Prompts

Prompt architecture — structure and technique per agent

Four agent-facing system prompts share one skeleton (Identity → Capabilities → Goals → Constraints → Output Format → Input). Three of them — Router, Docs and Web Search — carry an extra Conversation history section ahead of Input, holding the session's last five turns; Escalation does not, because it summarises the current case for an operator rather than continuing a conversation. A fifth prompt, supportflow/docs-translate — an internal search-term extraction step inside Docs Agent, not diagrammed here — is a plain instruction with no such structure. All five are managed as versioned text prompts in Langfuse Prompt Management (scripts/seed_prompts.py), never hardcoded. Content below is structural — the sections and their key rules, not the full prompt text.

Router — supportflow/router

The one prompt every request passes through. No tools, no retrieved content — the masked customer message plus the session's prior turns in, a classification out. History matters here too: "а скільки вони коштували?" is only classifiable against what was asked before it.

Docs Agent — supportflow/docs

Reads two pre-fetched sources — knowledge-base passages and Silpo catalogue results — that code retrieved before this prompt ever runs. The model never decides to call a tool.

Web Search Agent — supportflow/web_search

Same read-only-retrieval shape as Docs, plus one rule the others don't need: a domain guardrail that refuses to answer questions unrelated to Silpo, even when the model could.

Escalation Agent — supportflow/escalation

The only prompt that takes case context (Router's classification, prior errors, whichever agent was tried) instead of retrieved documents — it composes a report, not a customer-facing lookup answer.

Prompt technique, applied

The taxonomy used above

  • Zero-shot — instructions and constraints only, no worked examples. What all four prompts actually are.
  • Few-shot — the same, plus 1+ example input/output pairs baked into the prompt, to anchor format or edge-case handling.
  • Chain-of-thought — the prompt asks the model to reason step by step before answering, usually surfacing that reasoning.
  • Self-consistency — sample the model N times, take the majority/most-consistent answer — a decoding strategy layered on top of any of the above, not a prompt structure by itself.
  • ReAct / tool loop — the model itself decides, mid-generation, to call a tool, reads the result, and continues reasoning — an agentic loop where tool use lives inside the model's own turn.

Why all four are zero-shot, and why none are ReAct

The seeding script says this outright: zero-shot is the deliberate starting point for every prompt in this project; a switch to few-shot or chain-of-thought only happens as a new Langfuse prompt version, and only after a measured golden-dataset run shows the zero-shot baseline actually falling short — never speculatively, never before that evidence exists.

None of the four are ReAct-style tool-calling loops either, even though "Docs Agent" and "Web Search Agent" sound like they'd naturally be agentic. Docs Agent's own prompt says it outright: "the tool calls themselves happen in code before you see this prompt, you only read their results below." Web Search Agent's max 5 tool calls constraint isn't a budget for model-initiated calls either — run_web_search() in Python code picks Tavily-then-DuckDuckGo before the prompt ever runs. In every one of the four prompts, "which tool, when" is a decision made by code, never by the model mid-generation.

The point of the pattern: in every one of these four prompts, "which tool, when" is decided by Python before the model is called, never by the model mid-generation. Routing itself is not a prompt at all — decide_route() in src/domain/routing.py is three plain if/return statements, doctested directly, costing no tokens and unable to invent a route. A fifth "Supervisor" prompt describing that same logic in prose was seeded here for a time and never called by any code path; it was removed rather than left to look live.

Experiments run against these baselines

Few-shot was the one unused technique above with a real candidate — ReAct is architecturally closed, chain-of-thought pays output tokens on tasks with no reasoning steps, and self-consistency has nothing to vote over given free-text answers. Two hand-written few-shot candidates were built and measured against the live production prompts (scripts/seed_candidate_prompts.py, scripts/compare_prompt_versions.py). Both results below say the same thing: neither candidate was promoted, and both prompts stay zero-shot. A negative result is still a result — it is why the technique strips above are unchanged.

How to read this

Both cases are paired by construction — the same cases run under production and candidate, so the comparison is within-case, not two independent samples. Docs: exact permutation p=0.297, judge noise floor (spread across 3 repeat runs of production alone) is 0.019 — the point estimate is smaller in magnitude than the noise the judge itself introduces between identical runs. Router: only 1 of 12 cases flipped between versions; McNemar's exact test on a single discordant pair returns p=1.0 by construction — the least significant value the test can return, because one flip out of twelve is indistinguishable from a coin toss. Neither whisker (Docs) nor point (Router) clears the zero-difference line by a margin either result's own sample size can actually resolve.

A bug was caught while reading the Router result the first time: this project's own verdict script checked whether any cases had flipped at all, not the p-value itself, so it originally printed "a difference was measured" for a result with zero statistical evidence behind it. Fixed and covered by a regression test (tests/infrastructure/test_compare_prompt_versions_verdict.py) before either number reached this page — the concrete reason the paired design and exact tests above exist, not a hypothetical one.

n=8 and n=12 detect only large effects. Neither result should be read as "few-shot doesn't help" in general — it means these two prompts, already carrying explicit zero-shot instructions that had already been tuned once against a measured baseline (Docs v9's own "concrete next step" requirement, promoted after an earlier ≈0.61 → 0.817 measured gain), had little headroom left for a few-shot layer to add to at this sample size. Both candidates stay seeded under the candidate label in Langfuse, unpromoted, for anyone who wants to re-run the comparison on a larger set.
